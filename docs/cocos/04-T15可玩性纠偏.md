# T15 可玩性复核与纠偏计划

修订：2026-09-16。适用范围：当前 `cocos/` 原型到 M2 验收。本文是纠偏执行依据；R1/R2 已获用户手测通过反馈，R3/R4 已实现并待手测，实际进展见 03；时长和数值为待试玩验证的设计目标。

## 1. 判断与证据

开发存在执行偏差，但没有证据表明需要推翻 Cocos、纯 TypeScript 逻辑或轻量物流防守的产品方向。当前实现证明了系统可以协作，尚未证明玩家愿意持续规划和调整。原方案已有正确的 M2 试玩门槛，进度推进没有落实它。

| 已核对事实 | 证据 | 对体验的判断 |
| --- | --- | --- |
| 首关只开放带、普通炮塔、墙，钻头、工厂与两类炮塔已预置 | [logistics.json](../../cocos/assets/resources/maps/logistics.json) 的 `allowed`、`buildings` | 玩家主要补线，未学习从矿点建立生产链 |
| 补 `(20,19)`、`(20,24)`、`(20,26)` 三格后，无后续操作即可击杀全部 7 敌获胜 | [tutorial.test.cjs](../../cocos/tests/tutorial.test.cjs) 首个用例，本次 44/44 回归通过 | 是有效集成样例，但布局选择和战中调整不足 |
| 当前失败用例主动拆掉两座预置炮塔 | 同文件第二个用例 | 证明能判负，不能证明正常资源取舍会形成有意义的挑战；不据此断言其他失败方式不存在 |
| 开战同时要求核心铜、普通炮弹、石墨重炮弹 | 地图 `waveStart` 与 [GameSession.ts](../../cocos/assets/scripts/application/GameSession.ts) | 教学同时塞入第四关内容，增加理解负担，却未增加玩家设计空间 |
| 正式菜单和 HUD 明确指导补三处缺口，开发实验入口与首关并列 | [GameApp.ts](../../cocos/assets/scripts/presentation/GameApp.ts) | 当前呈现仍以演示与调试为主，缺少逐步放手的教学 |
| 原计划要求 5 人试玩后扩内容，原进度末尾却直接进入 T16 | 02/03 文档修订前内容 | 把「已实现」当成「阶段通过」，把关键体验推迟到存档和内容扩展之后 |

本次结论来自文档、配置、代码和自动回归，未新增真人试玩数据。主观趣味仍须实测；不能把下面的目标填写成已达成。

## 2. 保留与调整

保留固定步长、建造事务、守恒物流、共享寻路、真实弹药、命中、胜负与测试。保留 3 种资源、10 类建筑、3 类地面敌人、5 关的首版上限。暂不增加电力、液体、科技树、随机地图、机甲控制、联网、每日任务或商业化。

将当前三缺口关卡保留为开发回归样例，正式首关另做；更新测试时同时区分「旧集成样例」与「正式教学验收」。新正式地图使用独立稳定 ID，更新入口与测试引用；以后改变地图规则时递增 revision。暂不为这些样例建设通用关卡编辑工具。

前移 T17 中妨碍实际建造的操作和反馈，前移 T19 中第二关的关卡验证。T16 存档仍必要，但在玩法稳定后实现；完整美术、设置页、其余三关和发布工作保持后续安排。素材来源和微信技术验证继续补齐。

## 3. 首关：先学会亲手搭建

目标约 5 分钟，铜一种资源；核心、钻头、带、普通炮塔为必学，墙可选。不出现煤、石墨厂和重炮。地图仍可用 48×48，初始视野聚焦矿点、核心和防守区域，避免用地图大小制造内容量。

| 环节 | 玩家活动 | 设计与反馈 |
| --- | --- | --- |
| 观察与首次生产 | 在矿点造钻头，向核心铺线 | 先只显示当前目标，矿点、带方向和铜到达核心可辨认；提示说明原因，不直接提交建筑 |
| 弹药供给 | 自己选炮位并连接铜线 | 展示射程、敌人入口和大致进攻方向；有炮无弹时明确标注缺弹，允许两条独立铜线，不强制提前教路由器 |
| 第一波 | 观察供弹与开火 | 第一条有效供弹建立后解锁「开始防守」，点击后给清晰倒计时；准备阶段允许暂停和纠错，不要求凑齐复杂材料 |
| 后续 2～3 波 | 扩产、补炮或缩短暴露线路 | 提前提示来敌变化，波间给操作窗口；允许暂停思考。撤去具体落点提示，至少一条线由玩家独立完成 |
| 结算 | 看懂结果，重试或体验第二关 | 展示核心剩余生命与本局关键供给问题；记录不足时只显示确知数据，不编造失败原因 |

教学可保证首波容易，但不预建整套终局防线，不以必须自毁炮塔制造失败。允许优秀的提前布局降低战中操作量，不能为了动作数量强制拆线或脚本断供。第二关承担更明确的持续决策验证。

准备期不得靠无限等待积累足以碾压全关的资源。R3 比较「准备阶段产量／库存上限」与「首次供弹后限制准备时长」两种做法，选择一种并在 UI 解释；不静默丢弃物品。最终规则、上限及暂停行为写回 01 和地图规格，再固定测试。现有 `waveStart` 自动开战语义在迁移前保持兼容，新开战命令和教学状态由会话处理，不能只由 UI 决定战斗状态。

## 4. 第二关：验证布局取舍

作为首版第二关的早期样本，目标 8～12 分钟、约 5～7 波；使用铜、路由器和墙，不增加资源系统。设置近处有限供给与较远扩产点，围绕核心设置两个可选防区。先以已有敌人和寻路规则组织压力，不依赖新 AI。

玩家应面对两类相互影响的选择：先把铜送核心扩大建设还是优先供弹；靠前集中火力缩短交战时间还是靠后保护补给、承担更长敌路。至少验证两套费用与线路明显不同的可胜布局，例如近矿紧凑防守与远矿扩产双炮线。通过地形、造价、供给距离和波次形成取舍，不硬性锁定唯一正确坐标。

初始最低配防线能扛首波，但不应无扩建包办全关。一次常见失误（例如少供一座炮塔）应有明确征兆与恢复窗口，而不是立即必败。缺弹、漏怪、线路被毁要能区分；恢复供给后玩家应看见火力和防守结果改善。断供验证需等待真实缓存耗尽，不能为了演示而立即清空炮塔库存。

## 5. 当前任务与依赖

估算为主开发有效工日，含关卡配置与一次内部调整，不含招募、设备等待、完整美术及额外试玩迭代；单人按顺序执行。每项完成后在 03 填写构建、证据路径、问题和实际耗时。

| 编号 | 工作 | 前置 | 估算 | 完成证据 |
| --- | --- | --- | --- | --- |
| T15-R1 | 保留旧样例，制作铜教学首关；开放钻头与自主炮位，逐步目标、开战确认、重开 | 当前 T15 | 2～3 天 | 从零亲手搭建两类供给的完整录像；正式入口不再只补三格 |

合计初估 8～12 天；R5 若不通过追加迭代并更新估算，不按日期自动过关。T03～T05 的真实微信构建、双端运行与包体，T10 的物流真机回归及多格建筑欠项继续独立追踪。多格建筑若拟从首版移除，需明确改写规格与测试范围，不能默认为完成。

R3 的数值表至少记录：初始铜、必要建筑成本、预留纠错资源、钻头产率、运输吞吐、炮塔耗弹率／伤害／射程、各波生命总量与间隔。预算至少容纳一套基础建设加一次短线重铺；增加炮塔不能在供给不足时无条件增加持续火力。优先调配置，只有现有规则确实无法表达目标时才补小范围逻辑，避免重做架构。

当前波次延迟从上一波最后一次出生计算，并非清场后计时。先按这一真实语义校准间隔；若引入清场休整，必须显式修改规则、测试与 HUD，避免文案显示「休整」却继续刷怪。

## 6. M2 验收：技术正确与玩家体验分别记录

技术回归保留物流守恒、建造事务、弹药与命中、胜负幂等。新增测试只覆盖实际引入的开战、准备期和关卡规则；参考布局自动通关是配置可解性的证据，不能代替触屏和真人体验。

试玩使用同一构建，至少 5 名未参与实现者，记录其同类游戏经验。首轮只提供游戏内提示，观察者不口头教学；帮助或中途退出均照实记录。每人先玩首关再玩第二关，可在失败后重试一次。以下是本轮小样本的继续开发门槛，不是市场留存或统计结论：

| 检查 | 通过目标 | 记录方法 |
| --- | --- | --- |
| 首次理解 | 至少 4/5 在首关 2 分钟内独立让铜进入核心，并能说明箭头方向 | 计时、首次误操作、是否接受帮助 |
| 自主防守 | 至少 4/5 在最多两次尝试内独立完成首关，能解释炮塔为何需要物流 | 建造顺序、通关耗时、停火原因复述 |
| 可诊断与恢复 | 至少 4/5 在额外的统一缺弹场景中找到问题，并让真实供给恢复开火 | 首次通关测量结束后再给诊断场景，记录原因与修复动作 |
| 有效选择 | 内部验证第二关至少两套不同布局可胜；至少 3/5 玩家作出能解释原因的扩产、分流或防线调整 | 记录调整前后供给与战况；点击次数不算决策 |
| 再尝试意愿 | 至少 3/5 在无要求情况下愿意重试、改布局或继续体验，并说得出想改变什么 | 询问下一步想做什么，不要求表态「好玩」 |
| 实际操作 | 无阻断建造／取消／查看状态的问题；相同误触若出现于至少 2 人，必须修正复测 | 触屏录像、设备与问题列表 |

试玩记录格式：构建标识、地图 revision、设备、经验、首铜时间、首供弹时间、各波操作、帮助次数、通关／退出原因、想改的布局、问题编号。性能与微信双端验收沿用 01 的独立指标，不能用桌面浏览器成绩代替。

未达标时按问题处理：不懂做什么先调目标和引导；知道但操作困难先调交互；只需等待先调预算、地形和波次；失败无从解释先补反馈；理解且可操作但不愿重试则复核第二关取舍。不得直接用多做三关、新资源或成长奖励跳过当前问题。

## 7. 通过后的开发顺序

M0/M1 技术与 M2 体验门槛均通过后，进入 T16 版本化存档，再完成 T17 剩余生命周期／设置、T18 选择解锁、T19 第三至五关与第二关整合、T20 加载及 Alpha 检查，随后 M4/M5。存档需包含已确定的教学与备战状态，避免玩法未稳定时先固定错误的存档契约。

从现在开始，进度记录分别标注「实现」「规则回归」「可视／触屏」「真人体验」「微信真机」，不再以 T 编号或自动测试数量表示游戏完成度。当前收集 R3 revision 2 与 R4 第二关 revision 1 手测反馈，修正后组织 R5；R1/R2 录像、真机等证据仍独立追踪，不进入 T16。
