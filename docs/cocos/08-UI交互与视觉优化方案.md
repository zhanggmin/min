# UI 交互与视觉优化方案

日期：2026-09-22。状态：方案已确定，待开发与验收。本文交付优化设计，不代表 UI、素材或暂停规则已经改造完成。

## 1. 目标与范围

将《供给前线》改为 **明亮轻量卡通风**，以手机横屏微信小游戏为主要使用场景，兼顾桌面预览。让玩家能看懂当前目标、找到操作入口、预测操作结果，并及时理解物流与防守状态。

已确定的范围与取舍：

- 战斗页面优先，串联主菜单、暂停与结算；地图编辑器和开发工具不做整体视觉改版。
- 暂停时允许立即建造、旋转和拆除；生产、运输、敌人、战斗及波次保持冻结。
- 保留现有地图、建造成本、物流规则、开战条件和战斗数值，不借视觉改版增加关卡、资源或建筑种类。
- 保留第二关体验入口，不新增存档或持久化解锁；退出本局仍需说明不会保存战斗进度。

相关背景：[重构方案](01-重构方案.md)、[可玩性纠偏](04-T15可玩性纠偏.md)、[第二关与手测](07-R4第二关与手测.md)。

## 3. 视觉规范

### 3.1 色彩与层级

采用清爽、圆润、易辨识的卡通机械风格。地图保持安静，建筑与运输承担主要视觉信息，面板服务当前操作。

| 用途 | 基准色 | 使用方式 |
| --- | --- | --- |
| 地形底色 | `#DDE8D5` | 浅灰绿，使用低对比地块变化 |
| 面板 | `#FFF9ED` | 暖白，搭配轻描边与小范围阴影 |
| 正文 | `#263F4A` | 深蓝灰，优先保证小屏可读性 |
| 选择与主要操作 | `#246DA8` | 选中描边、当前工具、确认建造 |
| 有效与完成 | `#2F7B52` | 有效预览、任务完成勾选 |
| 提醒 | `#A65B13` | 缺料、停收、需要关注的状态 |
| 危险与拆除 | `#B94040` | 核心危险、无效预览、拆除目标 |

状态必须同时有图标、文字或轮廓，不单靠颜色判断。正文不使用浅色直接叠在浅地形上；重点按钮采用深底浅字，具体组合须在真实设备截图中检查。

### 3.2 建筑、地图与动效

- 核心：蓝色控制站，具有明显中心标识；钻头：黄色钻机，输出口与朝向清晰。
- 传送带：灰蓝底座、明确方向箭头和可见货物；炮塔：清晰炮管与弹药状态；墙体：灰色模块。
- 矿点保留铜色颗粒特征，避免与黄色钻头混淆；敌人入口用红色标识和进入方向，区别于玩家建筑。
- 浏览时弱化格线；进入建设时强化可操作区域附近网格、建筑预览和输出箭头。炮塔射程仅在选中或预览时显示。
- 建造成功使用短促落地反馈，库存同步变化；告警不持续大幅闪烁。装饰动效不能遮挡货物、敌人或落点。
- 素材先覆盖首两关实际用到的建筑、矿点、敌人和 UI 图标，再统一其余已有建筑。建立素材来源与署名记录，文档阶段不要求产出完整素材。

### 3.3 字体与触控

以最终显示的逻辑尺寸验收，主要触控目标至少 44×44，正文至少 14；面板说明左对齐，按钮标签居中。长说明换行或展开，不能依靠无限缩小字号适配。

采用 4、8、12、16、24 的间距阶梯，统一圆角、描边、按压、选中和禁用样式。尺寸不是原 1200×720 设计坐标中的固定值，必须结合屏幕缩放验证。

## 4. 页面布局与信息架构

### 4.1 战斗页

布局为“顶部状态栏 + 地图主体 + 底部建造栏 + 按需展开详情卡”。

```text
┌──────────────────────────────────────────────────┐
│ 关卡  核心生命  建材       备战 / 波次        暂停 │
├──────────────────────────────────────────────────┤
│ 当前目标 / 进度（可展开）                         │
│                                                  │
│                   地图主体                       │
│ 核心、矿点、入口标签                按需详情卡   │
│                                     当前操作     │
│                                   缩放 / 归位    │
├──────────────────────────────────────────────────┤
│ 钻头及成本  传送带及成本  炮塔及成本  墙及成本    │
└──────────────────────────────────────────────────┘
```

- 顶部展示关卡、核心生命、当前建材、备战或波次状态及暂停入口；品牌大标题退出战斗主视区。
- 准备阶段的任务卡突出当前一步，展开后显示全部开战条件；战斗阶段切换为波次、敌情及真实出生倒计时。
- 波次倒计时沿用实际调度规则，不将“距离下一次出生”误写成“清场后的休息时间”。
- 地图默认标注核心、铜矿和敌人入口；首次教学完成后收起常驻名称，选中时重新显示。空弹炮塔增加标识，点击告警可定位对应炮塔。
- 底部直接展示首两关允许建筑的图标、名称和价格，选中项有边框；建筑数量增加后允许横向滚动，不缩小每项触控区域。
- 详情卡仅在选择工具、选中建筑或预览时出现，空白浏览时收起。常规横屏放右侧；可用逻辑宽度小于 800 时使用右侧紧凑卡，次要详情折叠，主要动作始终可见。
- 缩放和归位合为小工具组，与建造确认、取消保持独立位置。

布局读取可用区域及安全边距，避开刘海、圆角和微信胶囊。地图裁剪、触摸换算、可见性判断使用同一份实际视口尺寸，移除固定可见范围对动态布局的限制。打开面板不修改世界坐标或造成选格漂移。

### 4.2 主菜单

使用明亮工厂插画和关卡卡片，呈现“采矿 → 运输 → 防守”的循环。第一关和第二关分别显示名称、目标和开始入口，第一关为主要入口，第二关保留体验标识。开发区为次要入口。没有续玩存档时不展示“继续游戏”。

### 4.3 暂停与更多菜单

暂停按钮冻结模拟，但保留地图建设能力，常驻“已暂停，可调整建设”与“继续”入口。更多菜单覆盖层提供继续、重开和返回主菜单，覆盖层拦截地图输入。

重开或离开需确认并明确说明“当前战斗进度不会保存”；取消后保留暂停状态。应用进入后台或回到前台都保持暂停，不自动恢复战斗。

### 4.4 结算

显示胜负、核心剩余生命、击杀和耗弹等已有统计；失败仅陈述核心被摧毁等已知事实，不自动推断布局失败原因。提供重试、返回菜单，以及首关胜利后的第二关入口。结算后停止建设操作，避免修改已经结束的局面。

## 5. 操作状态与反馈

### 5.1 建设状态表

| 状态 | 信息 | 可执行动作 |
| --- | --- | --- |
| 空白浏览 | 简短操作提示，详情卡收起 | 单指拖地图，点击建筑检查，双指平移缩放 |
| 已选建筑工具 | 用途、单价、输出方向 | 选择位置、取消；需要方向的建筑可旋转 |
| 有效预览 | 轮廓、方向、数量与总价 | 建造、旋转、取消 |
| 无效预览 | 缺铜、占用、矿点不符等具体原因 | 修改预览、取消；禁用建造提交 |
| 检查建筑 | 生命、库存、工作状态 | 适用时旋转、进入拆除、关闭详情 |
| 拆除预览 | 目标红色轮廓、返还资源、销毁库存 | 确认拆除、取消 |

保留“预览后确认”的基本流程。成功后清除本次预览，保留已选建筑以便连续建造；失败保留预览和原因供玩家修正。尚未执行的提交显示处理中，不能重复确认同一份计划。

### 5.2 传送带与手势

- 传送带拖动显示完整折线路径、方向、格数和总价；提供“切换拐弯”，在两种正交折线方案之间切换。
- 整条路径统一校验；有任一无效格或资源不足时，禁止整批落地，不部分扣费。旋转仍用于末端输出方向，不能悄悄修改整条路径。
- 浏览时单指平移；建造时单指设置或调整预览；双指平移和缩放。进入双指操作时取消未提交预览，保留工具选择。
- 按钮仅在同一触点按下并在按钮内抬起时执行，拖出或取消不执行；UI 区域不向地图透传输入。
- 拆除保留现有 50% 向下取整返还规则，并明确显示库存销毁量；不得拆除核心。

### 5.3 分层反馈

- 成功：落点短动画与资源变化，短提示自动消失。
- 校验失败：落点或详情卡显示具体原因，直到预览被修正或取消。
- 持续状态：暂停、核心危险、缺弹保持独立提示，不被“操作成功”覆盖。
- 区分无弹药、输出受阻和生命受损；只展示逻辑已知事实，不把所有停机都称为“断供”。

## 6. 教学与资源表达

按“采矿 → 送入核心 → 炮塔供弹 → 开始防守”推进，每次只突出一个动作。使用已有教学阶段和实际物流结果驱动完成状态，适度高亮矿点、核心或工具，不自动代建，也不强制玩家采用固定坐标布局。

将目前“建材铜 / 备战入库 / 开战解除”拆为三类信息：

| 位置 | 信息 | 示例 |
| --- | --- | --- |
| 建材栏 | 当前可花费库存 | 铜 64 |
| 任务卡 | 实际开战门槛及完成进度 | 铜送入核心：当前 / 目标；炮塔弹药：当前 / 目标 |
| 规则说明 | 准备阶段累计接收上限 | 准备阶段核心最多累计接收 24 铜，开战后解除 |

数值从地图与会话状态读取，不能把示例的 24 硬编码为所有关卡规则。达到上限后提示“核心暂时停收，继续准备炮塔供弹”，避免玩家误以为传送带故障。达标后出现“开始防守”，未达标时明确指出尚缺条件。

## 7. 技术落地与暂停建设

### 7.1 展示层组织

逐步将当前集中在 GameApp 的布局、按钮状态和面板更新拆为状态栏、建造栏、详情卡、暂停菜单和结算组件。统一视觉变量与按钮状态；领域状态仍由会话和世界提供，UI 不另算资源、开战条件或战斗结果。

地图渲染和输入共享视口参数。素材替换可分阶段进行，但一条首关完整流程中不可混用两套按钮状态语义。

### 7.2 命令接口调整

暂停建造属于行为变更，必须通过 GameSession 的统一命令执行路径处理，UI 不直接修改 World。

- 保留现有命令类型、命令复制、FIFO 顺序、执行时重新校验和独立结果序号。
- 抽取共享命令执行逻辑，并增加暂停期间处理待执行命令的入口。暂停建设提交后立即处理，建筑和库存随结果刷新，不推进世界 tick。
- 正常运行仍在逻辑步边界处理命令；暂停前已入队但未执行的命令先按原顺序处理，不能被后提交的建设操作超越。恢复后不得再次执行已处理命令。
- 暂停期间不推进生产、货物运输、敌人移动、射击、波次或冷却。仅建设相关变化立即生效，避免用额外模拟一步实现暂停建设。
- 命令结果的 tick 表示实际生效时刻：正常逻辑步沿用其步编号；暂停处理记录当前 tick，使用 sequence 区分同一 tick 的多次操作。
- 暂停时开战按钮标为“开始防守并继续”。先按真实状态校验并执行开战，成功后恢复时钟；失败则保持暂停并显示缺少条件。开战成功本身不额外推进模拟。
- 应用失焦只暂停模拟，不自动恢复；终局拒绝新的世界修改，并清理未执行命令。

无需新增外部 API 或存档格式迁移。现有关于“暂停时命令等待恢复”的测试需要按新行为更新，不能继续作为正确性基线。

## 8. 实施阶段

| 阶段 | 工作 | 出口条件 |
| --- | --- | --- |
| P0：操作与反馈 | 建设状态、按钮可用性、输入隔离、暂停即时建设、状态栏与菜单职责拆分 | 核心操作回归通过，暂停建设不推进模拟，不出现重复执行 |
| P1：整体视觉与适配 | 视觉变量、首两关素材、地图层级、动态视口、安全区、建造栏与详情卡 | 首关完整流程视觉一致，目标横屏尺寸无重叠、截断或选格偏移 |
| P2：流程与可玩性验证 | 主菜单、教学提示、告警定位、结算，复用至第二关并统一其他已有建筑 | 真机与非开发者试玩有记录，遗留项明确，不用自动测试替代手测 |

每阶段完成后更新开发进度中的实际结果；本方案发布不等于上述阶段完成。UI 改版不调整原有第二关数值验收结论。

## 9. 验收清单

### 9.1 自动回归

- 浏览无确认建造；无效预览不可提交；快速重复确认不会重复入队。
- 连续建造、折线切换、末端旋转、取消、整批成本与拆除返还正确；批次失败不部分扣费。
- 暂停建造立即落地扣费，旋转和拆除即时生效；世界 tick、货物、生产计时、敌人、战斗和波次不推进。
- 暂停前后命令保持 FIFO、按实际资源重新校验、结果序号独立；恢复不重放，不补算后台时间。
- 暂停开战重新校验实际供给，成功后恢复，失败保持暂停；终局拒绝修改。
- 更新现有会话、建设交互、教学及备战测试中依赖旧暂停语义的断言，保留规则正确性和资源守恒检查。

执行 Cocos 工程的 `npm run typecheck`、`npm test`，复核首两关现有规则场景。测试结果需记录执行日期与失败项，未执行不能标记通过。

### 9.2 布局与真机

- 覆盖 16:9、长屏手机及 4:3 横屏；验证最小字号、44×44 触控目标、安全区、详情卡和长文本。
- 验证打开详情、缩放、归位后的选格准确性；双指手势、拖出按钮与触摸取消不误建、不穿透。
- 暂停后建造、切后台再返回、重开确认取消、首关胜利进入第二关均符合设计。
- 分别记录桌面预览、iOS 微信和 Android 微信检查结果；同场景对比改版前后性能，不能用合成压力数据替代完整战斗表现。

### 9.3 试玩与证据

邀请至少 5 名未参与开发的玩家，不提供口头操作指导。目标至少 4 人依靠游戏内提示完成首次采矿与核心供给，并能说明建材、炮塔弹药及暂停状态的区别。记录完成情况、误触位置、反复寻找的入口与不理解的文案。

保留同关卡、同状态的改版前后截图，至少覆盖空白浏览、有效建设、无效预览、暂停建设、缺弹提示和结算。记录真机触屏流程及遗留问题。试玩比例是验收目标，当前尚无验证结果。
