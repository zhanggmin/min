# Cocos 开发进度

更新：2026-09-15。工程：仓库根目录 `cocos/`，Creator 版本锁定为 **3.8.8**（本机也已安装）；规划中的 4.0 文档引用不代表项目版本。

## 当前可用能力

- Boot / Menu / Battle 场景、物流与敌袭实验场、占位图形、地图浏览缩放、批量铺带预览、旋转和拆除。
- 地图校验、核心库存、钻头、带、路由器、交叉器、仓库和石墨工厂；纯 TypeScript 物流守恒测试。
- 普通／重型炮塔、铜／石墨弹药、敌人护甲、空间查询、逻辑子弹和扫掠命中；敌袭实验场已有可持续供弹的普通炮塔。
- 600 建筑、120 移动标记、240 子弹标记的合成显示负载。标记没有战斗逻辑，不能作为完整压力场景验收。

## T11 会话基础

- `GameSession` 成为界面更新入口：命令复制入队，按提交顺序在下一逻辑步执行，随后推进采矿／加工／物流。执行结果包含序号和 tick；失败命令保留原有事务校验。
- 暂停时可提交命令，界面提示排队，继续后执行；前后台切换清空时间积压，恢复后保持暂停。
- 可保存 uint32 状态的种子随机数；会话复制地图，避免调用方修改地图或建造预览改变已提交输入。
- 修复 0.15 秒因浮点误差只推进两步的问题。每步 0.05 秒，单帧最多四步，超额时间丢弃。
- 可选 `waves` 配置与 `WaveScheduler`：敌人类型、出生点索引、数量、延迟和间隔使用整数 tick；达到敌人数上限时，生成回调返回 false，游标保留并在下一步重试。
- 波次时间定义：首波延迟从战斗开始计算，后续波延迟从上波最后一次成功出生后计算；同一波出生间隔从上次成功出生后计算；每步最多出生一个敌人。
- 波次调度器已接入敌人系统；物流地图仍不配置波次。`complete` 仅代表全部出生，不能直接当成胜利条件。
- 补齐 TypeScript ES2016 标准库声明，修复现有 `includes` 类型检查错误。

## 本轮实现：T12 敌人移动与挡路攻击

- `DistanceField`：全体敌人共用反向 Dijkstra 距离场；岩石不可通行，空地代价 1、非核心建筑代价 9。建筑代价为固定破坏惩罚，不按血量实时重算。
- 建筑增删触发刷新，每步最多弹出 256 个堆条目，完成后统一替换距离数组；刷新期间继续使用旧场。初始化成本数组仍是一次地图大小的扫描，256 是扩展预算，不是总耗时保证。刷新期间再次变化会在下一轮重算，避免持续建造使缓存永远不能发布。
- 三类敌人的速度、生命、攻击伤害和攻击间隔集中配置；20 Hz 移动、邻格攻击。当前尚无炮塔、子弹及敌人受伤／护甲结算，后续由 T13 接入。
- 敌人预占来源格和目的格，拥堵时等待或选择下降方向的空邻格；禁止在预占格建造。出生点占用或达到 120 敌人上限时，保留波次游标并延后出生。
- 建筑新增生命值。敌人摧毁建筑不返还建材，内部物品只销毁记账一次；核心归零立即冻结会话，实验界面允许重开。此为实验流程保护，完整胜负与结算仍属于 T14。
- 地图校验拒绝被不可破坏岩石隔断的波次出生点。
- 新增 `maps/pathfinding.json` 和菜单“敌袭实验：封路与拆墙”入口；展示普通／快速／重甲敌人、建筑血条、核心生命、出生倒计时和敌人数。该实验没有胜利目标，可通过暂停、建墙、拆墙观察寻路行为。

## 本轮实现：T13 炮塔、弹药与子弹命中

- 新增纯逻辑 `CombatSystem`。普通炮塔只接收铜，重型炮塔只接收石墨；有合法目标时才扣除一发弹药并进入整数 tick 冷却。
- 两类炮塔使用独立射程、射速、伤害、穿甲和弹速。重甲敌人增加固定护甲，重型炮塔可完全穿透；伤害最低为 1。
- 每个战斗 tick 重建轻量空间网格，炮塔在范围内按距离和稳定敌人 ID 选取目标。逻辑子弹追踪目标并使用线段扫掠，避免 20 Hz 步长下穿透。
- 敌人死亡只结算一次，并同时释放来源格和目的格预占；同一步后续子弹会忽略已死亡目标，不重复统计命中或击杀。
- `GameSession` 的每步顺序扩展为物流、刷怪、敌人移动／攻击、炮塔／子弹；相同输入在不同渲染帧分割下保持一致。
- 敌袭实验场新增“钻头 → 传送带 → 普通炮塔”的真实供弹线，并开放两类炮塔建造；界面显示子弹、敌人血条、击杀数、缺弹状态和炮塔弹药量。
- 补齐 `tools/build.mjs`、`preview.mjs`、`package-report.mjs`。构建脚本验证最新产物并兼容本机 Creator 成功后退出 36 的行为；预览服务限制在构建目录内。

## 本轮实现：T14 胜负、结算与重开

- `GameSession` 增加稳定的 `playing`、`victory`、`defeat` 结果。只有最终波全部成功出生且存活敌人为零时才胜利；核心生命归零始终优先判负。
- 结果产生后清空未执行命令、暂停时钟并拒绝继续推进，避免重复结算或在结束画面后台继续模拟。
- 敌袭 HUD 显示明确的胜利／失败结果，原暂停按钮切换为“重开”；重开重新载入 Battle，创建干净会话。

## 本轮实现：T15 第一关教学闭环

- 原物流实验场升级为正式首关配置 `tutorial-01`：保留核心铜线和煤加工线，新增普通炮塔铜弹线，并把石墨线终点改为重型炮塔。三条线各留一个明确缺口。
- 地图格式增加可选 `waveStart`，可用“送入核心的资源”和“两类炮塔内的实际弹药”声明开战门槛。配置校验拒绝空条件、负数、未知资源、无波次条件和不可用的煤弹药。
- `GameSession` 在每个物流步后检查真实供给状态；首关达到核心铜 5、普通炮弹 3、重炮弹 2 后才启动波次倒计时。新增逻辑均补充中文注释，说明教学门槛与 UI 共用状态的原因。
- 菜单入口改为“开始第一关”，战斗 HUD 在备战期显示三项目标进度，达标时提示敌袭倒计时，战斗期切换为核心生命、波次、敌人数和击杀数，最终显示胜负与重开。
- 首关包含 4 个普通敌人和 3 个快速敌人。正确补线可稳定全歼；开战后拆除两座预置炮塔会导致核心失守，形成可胜可败的完整流程。
